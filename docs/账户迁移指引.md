# 账户迁移操作指引：更换 AWS 账户与 DeepSeek 账户

本指引写给接手这套服务的运维负责人。两件事的难度完全不同：换 DeepSeek 账户只是改一行配置再重启，十分钟的事；换 AWS 账户是把服务器整个搬家，认真做也就一两个小时，但有几个容易漏的环节。先讲简单的。

费用与账单的日常管理(充值入口、改绑银行卡、账单查看)见《项目报告》第 10 章,本文只讲"换账户"这个动作本身。

一条贯穿全文的原则:任何密码、API 密钥、.pem 私钥都不进 git 仓库,只存在于服务器的 `/opt/jiayi/service/.env`(权限 600)和你本地的凭据记录里。

---

## 一、更换 DeepSeek 账户

### 1. 新账户准备

1. 到 platform.deepseek.com 用新邮箱注册。
2. **先充值**。DeepSeek 是预付费模式,绑卡不等于自动扣款,余额为零时接口直接拒绝。建议先充 5 到 10 美元。
3. 控制台创建 API Key。密钥**只在创建时显示一次**,当场保存到你的凭据记录里。

### 2. 服务器上替换

```bash
ssh -i <你的密钥.pem> ubuntu@<服务器IP>
vim /opt/jiayi/service/.env      # 把 DEEPSEEK_API_KEY= 后面换成新 key
sudo systemctl restart jiayi
```

其他配置一概不动:`DEEPSEEK_MODEL=deepseek-v4-flash` 与账户无关,新账户同样可用。

### 3. 验证(三项都要做)

1. 健康检查:`curl http://127.0.0.1/api/health` 返回正常。
2. 网页上做一次完整评估,结果页的建议应为 AI 生成。注意一个设计特性:**key 无效或欠费时页面不会报错**,服务会自动降级为内置模板并照常返回,只在响应里标注 advice_source=template。所以"页面能打开"不代表新 key 生效。
3. 最硬的验证是行前查询:查一个具体国家(比如 Singapore),返回里 search_status 应为 ok。这条路径走按次计费的联网搜索,能同时证明新账户的鉴权和扣费都正常。

### 4. 收尾

- 新 key 验证通过后,回旧账户删除旧 key。
- 旧账户的剩余余额无法转移(预付费),可以留着这个账户把余额用完,或直接放弃。
- 本地开发机如果也需要真实调用,同步更新本地 `service/.env`。

## 二、更换 AWS 账户(服务器搬家)

服务对 AWS 没有任何深度绑定:它就是一台 Ubuntu 虚机加一个 systemd 服务,不用 RDS、不用 S3、不用负载均衡。所以搬家的思路是**新账户开新机、部署、验证,全部确认后再关旧机**,中间服务不中断。

### 第 1 步:新账户开 Lightsail 实例

1. 注册新 AWS 账户,绑一张能通过风控的银行卡(经验:美国发行的卡最稳)。
2. 进 Lightsail,Create instance:
   - 区域:俄勒冈 us-west-2(与现役一致),或者离主要用户更近的区域
   - 系统:Linux,Ubuntu 24.04 LTS
   - 套餐:2 GB 内存档(现役同款;1 GB 也能跑,余量小一些)
3. SSH 密钥:用账户默认密钥或新建一个,**下载 .pem 文件妥善保存**,丢了就进不去这台机器。本地放到 `~/.ssh/`(Windows 是 `%USERPROFILE%\.ssh\`)。
4. 强烈建议:Networking 页签创建一个**静态 IP 并绑定到实例**。不绑静态 IP 的话,实例每次停机再开 IP 都会变,后面第 5 步改过的引用又要全部重改。
5. 防火墙:实例的 Networking,IPv4 Firewall,确认 22(SSH)和 80(HTTP)两条规则存在。

### 第 2 步:部署

完整的英文部署文档在 `service/README.md` 的 Deployment 一节,以下是中文速记。在你本地的仓库根目录:

```bash
tar czf /tmp/jiayi.tar.gz --exclude=.venv --exclude=__pycache__ --exclude='*.pyc' \
  --exclude=.pytest_cache --exclude=.git --exclude=service/data --exclude=model/data \
  --exclude='.env' --exclude='*.pem' --exclude=account.txt model service
scp -i ~/.ssh/<新机密钥>.pem /tmp/jiayi.tar.gz ubuntu@<新IP>:/tmp/
```

SSH 到新机:

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip

sudo mkdir -p /opt/jiayi && sudo chown -R $USER:$USER /opt/jiayi
tar xzf /tmp/jiayi.tar.gz -C /opt/jiayi
cd /opt/jiayi/service

python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt

cp .env.example .env && chmod 600 .env
vim .env
mkdir -p data

sudo cp deploy/jiayi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now jiayi
```

`.env` 的生产配置,对照着填:

| 配置项 | 生产值 | 说明 |
|---|---|---|
| DEEPSEEK_API_KEY | 真实密钥 | 见本文第一部分 |
| DEEPSEEK_MODEL | deepseek-v4-flash | 与现役一致 |
| MOCK_MODE | false | **建议先用 true 起服务验证部署,确认后改 false 再重启** |
| EVAL_LOG_PATH | data/assessments.jsonl | 打开评测回流 |
| HOST / PORT | 不用管 | 生产端口 80 写死在 systemd 单元的 ExecStart 里 |

联网搜索的三个开关(SEARCH_ENABLED 等)默认值就是生产值,不用显式设置。

### 第 3 步:迁移评测回流数据(建议做)

旧机上的 `/opt/jiayi/service/data/assessments.jsonl` 是阈值本地校准的原始积累,搬过来:

```bash
scp -i <旧机密钥>.pem ubuntu@<旧IP>:/opt/jiayi/service/data/assessments.jsonl /tmp/
scp -i <新机密钥>.pem /tmp/assessments.jsonl ubuntu@<新IP>:/opt/jiayi/service/data/
```

### 第 4 步:验证新机

浏览器打开 `http://<新IP>`,完整走一遍:做一次评估、追问一个问题、查一个目的地。同时在新机上 `journalctl -u jiayi -f` 盯着日志确认无报错。

### 第 5 步:更新所有写着旧 IP 的地方

这是最容易漏的一步。旧 IP(35.88.114.45)目前出现在:

1. `README.md` 顶部的 Live service 链接
2. `CITATION.cff` 的 url 字段
3. `service/README.md` 的 Live 行
4. GitHub 仓库设置里的 homepage(仓库页右上 About 的齿轮,或 Settings)
5. `docs/technical-report.html` 与对应 PDF(两处)
6. `docs/项目报告.html` 与 `docs/project-report.html` 第 10 章的账户表,及各自的 PDF

前 4 处是几分钟的事,改完提交。两份报告的 HTML 改起来也快,但改后需要用 Edge 无头模式重新生成 PDF;如果暂时不想动报告,至少在交接记录里注明"报告内 IP 为旧地址"。

另外更新你本地凭据记录里的服务器 IP 和 SSH 命令。

### 第 6 步:关旧机,停止扣费

**铁律:先让新机稳定跑几天,再动旧机。**

1. 旧账户 Lightsail 里删除实例。
2. 如果旧实例绑过静态 IP,删除实例后把静态 IP 也释放掉:**未绑定实例的静态 IP 是单独计费的**,这是 Lightsail 最常见的"僵尸账单"。
3. 旧 AWS 账户如果整体弃用:到 Billing 确认没有未结账单和残留资源后,可在账户设置里注销。

## 三、快速核对清单

换 DeepSeek:

- [ ] 新账户已注册并**充值**
- [ ] 新 key 已写入服务器 `.env`,已 `systemctl restart jiayi`
- [ ] 三项验证通过(health / 评估建议为 AI 生成 / 行前查询 search_status=ok)
- [ ] 旧 key 已删除

换 AWS:

- [ ] 新实例已开,**静态 IP 已绑定**,防火墙 22/80 开放
- [ ] 部署完成,先 MOCK_MODE=true 验证,后改 false
- [ ] assessments.jsonl 已迁移
- [ ] 新 IP 完整走通评估、追问、行前查询
- [ ] 六处旧 IP 引用已更新(README / CITATION / service README / GitHub homepage / 两份报告)
- [ ] 新机稳定运行数日后,旧实例已删除、静态 IP 已释放

## 四、常见坑

- **DeepSeek 欠费不报错。** 服务设计为降级而非失败:欠费时页面一切正常,只是建议悄悄变成了模板。判断标准是行前查询的 search_status 和响应里的 advice_source,不是"页面能不能打开"。
- **Lightsail 静态 IP 不绑实例也收费。** 删实例记得释放 IP。
- **.pem 丢失无法找回。** AWS 不保存你的私钥,丢了只能给实例换密钥对(麻烦)或重建实例。
- **先删旧机再发现新机有问题**是唯一不可逆的操作顺序错误。本指引的所有步骤里,只有"删除旧实例"无法撤销,把它放在最后,并且隔几天再做。
