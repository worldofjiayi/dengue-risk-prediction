# 更换银行卡操作指引(AWS 与 DeepSeek)

本指引只讲一件事:把 AWS 账户和 DeepSeek 账户的付款银行卡换成另一张。**账户本身、服务器、API 密钥、服务配置全都不动**,服务不会中断,也不需要登录服务器。全部操作都在两个平台的网页控制台里完成,合计十几分钟。

先说清楚两个平台扣费方式的根本区别,后面的操作逻辑都由它决定:

| | AWS | DeepSeek |
|---|---|---|
| 扣费方式 | **后付费**:每月自动从默认付款方式扣上月账单 | **预付费**:手动充值进余额,平台从不主动扣卡 |
| 换卡的实质 | 换掉"下月会被自动扣款"的那张卡 | 下次充值时用新卡付款即可 |
| 不换的后果 | 旧卡失效会导致扣款失败、账户欠费 | 没有后果,余额用完前无感 |

---

## 一、AWS 换卡

AWS 每月自动向默认付款方式收取 Lightsail 月费,所以换卡要赶在旧卡失效或注销之前完成,否则会出现扣款失败。

### 操作步骤

1. 用账户 jiayichen 的根用户邮箱登录 <https://console.aws.amazon.com>。
2. 右上角账户名下拉,进入 **Billing and Cost Management**(账单与成本管理)。
3. 左侧菜单找到 **Payment preferences**(付款首选项)。
4. 点 **Add payment method**,填入新卡的卡号、有效期、安全码和账单地址。经验提醒:这个项目注册云账户时曾有卡被风控拒过,**美国发行的信用卡通过率最高**;添加时 AWS 可能对新卡做一笔小额预授权验证,属正常现象。
5. 新卡添加成功后,在它旁边选 **Set as default**(设为默认付款方式)。
6. 回到列表把旧卡 **Remove**(删除)。注意顺序:AWS 不允许删除当前默认卡,必须**先把新卡设为默认,才能删旧卡**。

### 验证

- Payment preferences 页面只剩新卡,且标记为 default,即算完成。
- 下一个月度账单会自动从新卡扣款。次月初可到 Billing 的 **Payments** 页确认扣款成功;如果扣款失败,AWS 会发邮件到注册邮箱(jiayichennbshangtian@yahoo.com)提醒并自动重试,届时在 Payments 页手动 **Verify and pay** 补扣即可。

## 二、DeepSeek 换卡

DeepSeek 开放平台(platform.deepseek.com)是预付费:钱是手动充进余额的,平台从不主动从卡上扣款。所以严格说 DeepSeek **没有"绑定的扣款卡"这回事**,换卡比 AWS 更简单:

1. 登录 platform.deepseek.com,进入充值页面。
2. 下次充值时,直接用新卡完成支付,就换完了。
3. 如果控制台的付费或账单设置里保存有旧卡的快捷支付记录,顺手删掉即可;没有就什么都不用做。

两点提醒:

- **账户余额不受换卡影响**。余额属于账户,不属于卡;旧卡充进来的钱继续正常消耗。
- 换卡不解决余额问题。DeepSeek 侧真正需要盯的是**余额是否充足**:余额耗尽时服务不会报错,而是静默降级为模板建议(页面照常打开,响应里 advice_source=template),联网搜索则直接停用。所以日常要紧的是定期看余额、及时充值,用哪张卡充反而无所谓。

## 三、核对清单

- [ ] AWS:新卡已添加并**设为默认**
- [ ] AWS:旧卡已删除
- [ ] AWS:次月初到 Billing 的 Payments 页确认首笔扣款成功
- [ ] DeepSeek:下次充值改用新卡(如有旧卡快捷支付记录则删除)
- [ ] DeepSeek:余额充足(这与换卡无关,但它才是 DeepSeek 侧唯一真正的风险点)

服务器、`.env`、API 密钥、GitHub 仓库:**全都不用动**。

费用构成、充值入口等日常账务管理的更多细节,见《项目报告》第 10 章。
